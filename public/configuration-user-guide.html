04

Your first practice setup

Build a small fictional organisation, create an inspection role and give Jamie a second role at another scope. Perform every step using Alex’s login. Names ending in “Practice” help you distinguish the exercise from the sample company.

About 15 minutesOne new hierarchyOne person · two scoped roles
1

Create the hierarchy from the top down

Use the four structure pages and their Create buttons:

  1. Business units: create Practice West Operations.
  2. Sites: create Galway Practice Hub; select Practice West Operations as its business unit.
  3. Locations: create Office Wing (Practice); select Galway Practice Hub as its site.
  4. Departments: create Field Services (Practice); select Office Wing (Practice) as its location.
What you should see: Every child row displays the parent you selected. The department belongs to the practice site through its location.
2

Create a focused role

Open Roles & permissions → Roles → Create role. Enter Practice Inspector and click Create empty role. Select the Inspection permission area. Choose View inspections & findings, Record checks & evidence and Complete inspections. Click Save changes.

What you should see: The role is in the searchable list with just the permissions you chose. It does not need general Configuration permissions to perform inspections.
3

Create Jamie and the initial assignment

Open Users → Create user. Enter Jamie Lee (Practice) and jamie.lee.practice@northstar.example. Choose Practice Inspector. Under Initial role scope, select the department Field Services (Practice). Click Create user.

What you should see: Jamie appears in Users with an active status and a department-scoped Practice Inspector assignment. No email is sent and Jamie cannot sign in with this address in the demo.
4

Add another role at the site scope

Open Roles & permissions → Assignments. In Add role assignment, search “Jamie” and select Jamie’s result. Choose the existing Form designer role. Set Scope level to Site, search for “Galway” under Find scope, and select Galway Practice Hub. Click Assign role.

What you should see: Jamie now has two assignments: inspection work at the department and form design at the site. Searching Jamie in the assignment directory shows both rows.
5

Check the result in Users

Return to Users and search “Jamie”. Read Role assignments. Then return to the assignment directory and use the role and scope-level filters to find each assignment separately.

What you should see: The user summary and assignment directory describe the same two assignments. There is no need to create a duplicate user for the second role.

Create and find a record

  1. Open the appropriate structure page.
  2. Click its Create button and enter Name.
  3. Select the parent when required. Add optional Notes to help others recognise the record.
  4. Submit the form. Search the page by name or details to find the new row.

A department’s site is determined through its location. For example, selecting Logistics identifies Warehouse, Cork Distribution and Operations. Create a missing parent before creating its child.

Current page controls. These lists demonstrate creation and searching. Their row ellipsis is not an implemented edit or move workflow. Changing a name, relocating a department or removing structure records needs a future administration workflow.

07

Define roles and permissions

A role is a named set of allowed actions. It answers “what can this person do?” A role assignment adds the scope: “where can they do it?”

1

Find or create a role

Open Roles & permissions → Roles. Search the role list and select a role to inspect it on the right. For a new role, use Create role, enter a clear name and click Create empty role. Duplicate role names are rejected.

What you should see: A new role starts with no permissions. A role’s name alone grants nothing.
2

Choose individual actions

Select a permission area, then check only the actions needed for that responsibility. A person who completes assigned work need not approve or verify everybody else’s work. Choose view permissions as well when the person must read the records they work on.

What you should see: The role describes specific actions in each area, rather than simply granting an entire module.
3

Save and check its assignments

Click Save changes. Use View people with this role to open the filtered assignment directory. If you change your mind, use Discard before selecting another role.

What you should see: Unsaved changes prevent switching to a different role. The assignment count counts assignments, so one person assigned at two scopes can contribute two.

Permission examples

AreaPossible responsibilities
RiskView, create, edit or approve assessments; create, assign, complete or verify tasks
IncidentReport, triage, investigate or close incidents; create, assign, complete or verify actions; manage recurring actions
AuditSchedule, create or conduct audits; record findings; publish reports; close audits
InspectionView, schedule, record checks, complete, raise follow-up, archive / restore or export
DocumentView, create, edit drafts, review, approve, publish, download or archive
LawView or manage the register and evaluation responsibilities in the permission catalogue
Form BuilderView form designs; create and edit drafts; publish versions; archive forms in the intended model
ConfigurationManage company structure, users or roles; run bulk import; change branding; view, manage or test scheduled jobs

Useful permission dependencies

  • Form publishing selects design and view permissions too. Removing view removes design, publish and archive selections; removing design removes publish.
  • Managing or testing scheduled jobs also selects view. Removing job view removes manage and test.
  • Other areas do not have a universal automatic “create also grants view” rule. Review the selections explicitly.
Access design for the future application. Saved permissions describe the intended access policy. Buttons are not restricted by these roles in the current admin-only presentation. Catalogue entries can also describe future capabilities; their presence does not mean every workflow is implemented.

Give one person several scoped roles

Role = what. Scope = where. Assign a role to a person at a whole-company, business-unit, site, location or department scope.

PersonRoleScopeIntended responsibility

1

Select the person

Open the Assignments tab. In Add role assignment, type at least two characters of a name or email, then click the correct result. Only the first eight matching people are shown; type more of the name when necessary.

What you should see: The form contains the selected user, rather than just typed search text.
2

Choose the role and exact scope

Select Role and Scope level. Whole company needs no additional record. For another level, type in Find scope and click the correct result. Scope results also show up to eight matches; refine the search if needed.

What you should see: The scope points to an actual structure record. Typing a name alone does not select it.
3

Assign and inspect

Click Assign role. Add a second role using the same user if appropriate. In Current assignments, search the user and use the role and scope-level filters. The directory paginates 20 assignments at a time.

What you should see: Each role/scope combination is a separate row. An exact duplicate assignment is blocked.

Correcting an assignment

Use the row’s remove control, then add the correct role and scope. This removes that assignment, not the user record. Alex’s sample whole-company EHS Administrator assignment is protected to keep the presentation usable.

How parent scopes should work in production. A site-scoped role should cover that site’s locations and departments for the actions in that role. A department-scoped role should remain local. Combine permissions within each applicable scope; a wider Form designer assignment should not widen a separate Inspector assignment. Scope enforcement and form ownership filtering remain future backend work.
09

Design forms and reuse fields

Suggested people: Sofia designs; Alex reviews and publishes. Form Builder supplies the forms used by Risk, Incident, Audit and Inspection workflows. This guide covers the builder rather than the operational completion of those records.

1

Look at existing forms

Open Form Builder → Forms. Search forms and use the module and status filters. Select a form to see its preview on the right. Preview answers are disabled. Use Continue editing for a draft or Create new draft for a published form.

What you should see: You can inspect a form without changing its published questions.
2

Start a new form

Open Create form. Enter Form name and choose Module. For Incident choose Report or Investigation; for Audit choose Standard, Scorable or Express; for Risk choose its scoring method. Click Start building.

Practice example: Practice equipment check, module Inspection.

What you should see: The form starts as Draft with mandatory module fields already included.
3

Add and arrange questions

In the right-hand COMPONENTS list, drag a component into the form or use Add. Select its field name to edit its label, required setting, guidance and, where applicable, choice options. Reorder by dragging or using the up/down controls.

Try a Dropdown named “Equipment condition” with options “Good”, “Needs attention” and “Unsafe”. Add a Long text field for comments.

What you should see: Each question appears in the form order you chose. Mandatory module fields cannot be removed, but their order and guidance can be changed.
4

Reuse an existing question

Under COMPONENTS → Reuse a created field, type part of a field name into Search field names. Click a matching field, checking the source form and module shown beneath it.

What you should see: A copy is added to the end of the draft with its settings and options. Move it where needed. Editing the copy does not change the source field.
5

Preview, then publish

Use Preview to inspect the draft. Continue editing if necessary. When the questions, choices and required fields are ready, click Publish version in the builder.

What you should see: The form becomes a published version available to compatible workflows. There is no separate Save draft button: draft edits update the prototype’s in-memory state as you work.
Publishing is a controlled responsibility. In the suggested role arrangement, Sofia drafts and Alex checks and publishes. A published form is not edited directly: create a new draft for changes, then publish a new version. Existing operational records retain their captured version. The current presentation lets Alex perform both responsibilities.

Use the Risk, Incident, Audit or Inspection guide for how a published form is used in its workflow.

Bulk configure from a CSV

Suggested person: Alex, after checking the file. Bulk import adds multiple records together and validates their relationships before adding anything.

Download the practice CSV ↓

Six rows: one business unit, site, location, department, role and user. The file uses the same names as the manual exercise, so choose one route for these names.

1

Prepare the file

Use a CSV file no larger than 2 MB. Keep the exact seven-column header below. Use unique keys to link children to parents. Save as CSV, rather than an Excel workbook.

What you should see: The file contains the required columns and readable names. A parent reference is either another row’s key or an exact existing parent name.
2

Upload and review every issue

Open Bulk import and select or drop the CSV file. Read the review counts and any row errors. Fix the file and upload again if required.

What you should see: Unknown parents, duplicate names or invalid values block import. Nothing has been added during validation.
3

Import once the preview is valid

Use the page’s import button when all rows are valid. Check the resulting structure and user lists. The import adds new records; it does not update or overwrite existing ones.

What you should see: All six practice rows are added together. Re-importing the same names is blocked as a duplicate, rather than updating them.
4

Assign the imported user explicitly

Open Roles & permissions → Assignments (or the import result’s Assign roles button). Find Jamie, select Practice Inspector, choose Department, find Field Services (Practice) and click Assign role.

What you should see: Jamie now has the actual scoped role assignment. The user row’s parent role in the CSV did not create that assignment by itself.

Configure reminders and scheduled jobs

Suggested people: Alex configures and tests; Ethan reads the rules and history. A scheduled job describes a repeating check, such as finding overdue work each morning.

Overdue reminders

Find records past their due date. Choose the overdue threshold and optional escalation after a longer delay.

Upcoming due dates

Warn owners about work due soon, for example in the next seven days. This is useful for risk reviews and equipment inspections.

EHS summary digest offers a summary of open work. The live bell preview uses eligible overdue/upcoming owner rules; a digest does not populate that preview.

1

Select or create a job

Open Scheduled jobs → Jobs. Select a job to read its rule, or click Create job. Enter a clear job name and select its job type. New jobs start paused.

What you should see: You are editing the rule for one job. A paused rule can still be tested after saving.
2

Set time, scope and records

Choose a daily, weekday, weekly or monthly frequency, Run at time and time zone. Weekly rules need a weekday; monthly rules use day 1–28. Choose the company or a narrower structure scope and the record types to check.

Example: “Practice equipment reminders”, Upcoming due dates, daily at 08:00, Europe/Dublin, and Risk reviews plus Inspections due within seven days.

What you should see: The summary describes the intended schedule and scope. The advanced cron expression is generated from the controls.
3

Choose delivery and escalation

Select assigned owners and any additional recipient roles, then email and/or in-app delivery. Choose a digest per recipient or a message per record. For overdue jobs, optionally choose an escalation delay and role.

What you should see: A recipient, channel and meaningful threshold are configured. An escalation delay must not be earlier than the initial overdue threshold.
4

Save before testing

Click Save job for a new rule or Save changes for an existing one. Click Test job and inspect the matching records. To enable or pause a rule, change its active setting and save again.

What you should see: The test lists matching items without sending messages. Unsaved or newly unsaved jobs cannot be tested. Save or Discard changes before switching jobs.
5

Read Run history

Open Run history. Filter by job or outcome and open Details. Distinguish your Test preview rows from the demonstration’s Sample scheduled run rows.

What you should see: Test rows show Preview only. Completed means the preview completed, not that email reached a recipient.

How the bell preview relates to these rules

The default Daily equipment & risk reminders rule covers upcoming Risk reviews and Inspections within seven days. The bell reads live due dates for those records and lets you filter by responsible person. Enabled overdue/upcoming rules need the appropriate target, scope, assigned-owner delivery and in-app channel to affect the preview.

What runs in this prototype. Risk reviews and Inspection dates are live in the app tab. Tests use illustrative records for the other modules. There is no background scheduler or email delivery. Sample history is demonstration data. Saving a rule or seeing a bell reminder does not mean a server executed a cron job.

Questions and practice checklist

Why is my site or department missing from a scope choice?

Create the hierarchy first. Check the correct level: a location belongs to a site, and a department belongs to a location. In the assignment search, refine the text because only eight matches are shown, then click the exact record.

Why does typing a user or scope name not allow assignment?

Typing searches for a record; it does not select it. Click a result, then choose the role and scope. User search starts after two characters.

Why did my imported user not get permissions?

Bulk import creates the user record. It does not create an explicit scoped role assignment. Go to the Assignments tab and add the user, role and scope there.

Why can I still use every page after making a limited role?

The working presentation login is Alex, and role-based restrictions are not enforced. Use the fictitious examples to agree responsibilities; production authorization needs backend enforcement.

Does changing a role apply to everyone who holds it?

A role is one shared permission definition. Assignments point to that definition, so changes are intended to affect all people assigned that role at their respective scopes. Review the assignment list before changing a widely used role.

Why can’t I edit a published form directly?

Create a new draft from its preview. Revise and publish the new version. Existing operational records keep their captured questions, so past work remains understandable.

Why is Test job unavailable or showing no matches?

Save the job first. Then check its type, targets, scope and date threshold. A valid test can have zero matches. Only Risk reviews and Inspection dates are live; other module test records are illustrative.

Why has no reminder email arrived?

Test job previews recipients and matching records without sending email. The bell is a live in-app preview for eligible Risk/Inspection rules. A production background scheduler and delivery service are not connected.

Why did my setup disappear after refreshing?

App records, forms, job settings and branding live in the current tab’s memory. Reload or sign-out restores the sample data. The guide’s practice ticks use separate browser storage when available.
